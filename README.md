# v36.8.3 (2026/11/19)
- 対戦を始めるときに、自分と相手の両方のデッキのカード画像(対戦中に使う小さい画像)を、すべて読み込んでから始めます。読み込みが終わるまで、最初のステップに入りません(最大8秒。時間がかかるときは「カード画像を読み込み中」と出ます。8秒を過ぎても、読み込みは続けます)。
- 効果や文面に「ソーディッシュ」と書いてあるカードが、どちらかのデッキに入っているときは、トークンのソーディッシュの画像も、同じように読み込みます。
- 拡大表示やカットインに使う大きい元画像は、対戦が始まったあとに、じゃまにならないよう少しずつ先に読み込みます(メモリには置きません)。
- 通信対戦の相手側(ゲスト)は、相手のデッキの中身を知らないので(知らないのが正しい)、自分のデッキだけを先に読み込みます。相手のカードは、出たときに読み込みます。

# v36.8.2 (2026/11/19)
- デッキ作成の一覧を、100枚ずつ作る形にしました。「収録」を選ばずに検索しても、全カード(約700枚)を一度に作らず、下へスクロールすると続きが出ます。カードを足したときも、全件の作り直しをしません。
- 検索欄は、文字を打ち終わってから(0.2秒後に)検索します。
- 画面が狭いとき(スマホ)も、見えているカードだけ画像を読み込むようにしました。

# v36.8.1 (2026/11/19)
- デッキ作成の画面で、カード一覧がなかなか表示されない問題を直しました。一覧を開くと、大きい元画像(約200枚・約40MB)をいっせいに読み込んでいたのが原因でした。小さい画像(約40KB)を、画面に見えているカードだけ読み込むようにして、読み込みの量を約6分の1にしました。
- 保存済みのデッキの画像を先に読み込むときも、小さい画像を使います。
- 小さい画像(cards/thumbs/)は、端末に30日間保存する設定(_headers)を追加しました。2回目以降は、通信せずに表示します。

# v36.8.0 (2026/11/19)
- カード画像が2秒たっても表示できないときは、カード名を代わりに表示します。画像の読み込みは続けていて、届いたら画像に切り替わります。読み込みに失敗したときも、間隔をあけて何度も読み込み直します。
- ターンの始まりを、1ステップずつ進める形にしました。スタート → 一拍 → コア(コアが増える動き) → ドロー(一拍おいてカードが手札に入る) → リフレッシュ(一拍おいて回復) → メイン、の順で、動きが終わってから次のステップに進みます。これまでは、スタートの時点で疲労の回復まで終わっていました。
- 重疲労がリフレッシュで疲労に戻るときも、疲労の回復と同じように動かします。
- エンドステップの効果がある場合は、効果と動きがすべて終わってから、相手のターンを始めます。
- 試合の記録(リプレイ)と、CPU同士の学習には影響しません。確認用に tools/pace_test.js を追加しました。

# v36.7.0 (2026/11/18)

# v36.6.0 (2026/11/18)
- 対戦中にカード画像が黒くなる問題の対策として、小さいカード画像(cards/thumbs/)を用意しました。手札や場の小さいカードは、これを使います。大きな画像を何十枚も同時に表示するのをやめるので、スマホでのメモリ不足が起きにくくなります。ソーディッシュの画像も含まれています。
- アプリ内の保存(sw.js)では、大きなカード画像を保存しないようにしました(保存領域とメモリを使いすぎていたため)。
- cards/thumbs/ が無い場合は、これまでどおりの表示になります。

# v36.5.0 (2026/11/18)
- 「戦局:樹根隆起」を、カードの文面どおりに直しました。コスト3以下のスピリット(トークンのソーディッシュを含む)は、すべて合わせてターンに1回しかアタックできません。これまでは、1体ごとに1回までになっていました。
- 対戦中にカード画像が黒くなることがある問題に対応しました。端末のメモリ不足で縮小画像が真っ黒になったときは、それを使わず元の画像を使います。縮小画像を作るときのメモリも早めに解放します。
- 対戦を始めるときに、両方のデッキのカード画像を先に読み込んでおきます。ソーディッシュを出すカードがあるときは、ソーディッシュの画像も用意します。
